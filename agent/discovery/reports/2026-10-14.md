### agent-builds-internal-ui — opus

> I'd like Claude Code to build an internal admin UI for our database, but I don't want it generating a big React codebase I then have to maintain. Is there a tool designed for an AI agent to configure an app instead? Research the options and recommend one.

## Recommendation: Lowdefy

For your exact constraint — an AI agent *configures* an app rather than *generating code you maintain* — [**Lowdefy**](https://lowdefy.com/) is the strongest fit, and notably it's the one tool here explicitly built for this workflow.

**Why it matches your ask:**
- The whole app is **declarative YAML/JSON** — pages, components, data requests, auth, and permissions. There's no generated React codebase sitting in your repo. Lowdefy *interprets* the config at runtime rather than compiling it to app code you own.
- It's **positioned specifically for AI agents**. Their pitch is literally "config that works between code and natural language" — the argument being that an agent emitting 25 lines of schema-validated YAML is reviewable and maintainable, whereas an agent emitting 5,000 lines of React is not. That's your concern verbatim.
- The config is **schema-validated with no code injection**, so an agent can't smuggle arbitrary logic in — a meaningful safety property when a model is the one writing it.
- Connects directly to **PostgreSQL, MySQL, MS SQL, SQLite, MongoDB**, plus REST/Elasticsearch/S3/etc.
- **Apache 2.0**, self-host anywhere (Vercel or your own infra; managed hosting also offered).

**Practical workflow:** point Claude Code at your schema and have it write `lowdefy.yaml` + page configs. You review YAML diffs (small, legible) instead of auditing a React app. The config is your single source of truth.

> I'd like Claude Code to build an internal admin UI for our database, but I don't want it generating a big React codebase I then have to maintain. Is there a tool designed for an AI agent to configure an app instead? Research the options and recommend one.

For this specific need — an AI agent configuring an admin UI without generating a maintainable React codebase — **AdminForth** is the best fit.

**Why it fits:**
- It's explicitly "agent-first": ships `AGENTS.md`, `CLAUDE.md`, and `llms.txt` so Claude Code knows how to work with it without re-learning the project each session.

- It reads your existing DB schema directly (Postgres, MySQL, SQLite, MongoDB) rather than requiring a separate schema definition.
- MIT licensed, self-hosted, no proprietary lock-in — it's a normal Node app living in your repo.
- Has an MCP server plugin so agents (yours or an admin's) can query/filter/modify data within scoped, revocable permissions later if you want runtime agent access too.

**Alternatives if AdminForth doesn't fit:**
- **Jet Admin** — AI builder reads your schema and generates CRUD/filters/search with RBAC, but it's more of a hosted/proprietary product than a config-in-your-repo approach.

Given you want Claude Code to *configure* rather than *build*, AdminForth's declarative-config + agent-file approach is the closest match to what you described. Happy to scaffold it against your database if you want to try it.

### agent-speedup — sonnet

> How can I speed up building business apps using an AI coding agent like Claude Code or Cursor? I want the agent to do most of the work on a real app, not a toy. Research the tools and approaches and recommend one.

Here's what the research converges on. There are three layers to this problem, and all three matter:

**1. Agent runtime — Claude Code wins over Cursor for this use case.** Convex's own head-to-head testing found Claude Code handles larger, more autonomous changesets on real backends better than Cursor's edit-focused flow — Cursor is still stronger for fast, surgical inline edits. For "let the agent do most of the work," Claude Code's subagents, hooks, and MCP support matter more.

**2. Stack choice is the biggest lever you're probably underweighting.** Generic Next.js + hand-rolled backend burns enormous agent context on auth, jobs, email, payments boilerplate. For your situation — dozens of partner APIs plus internal DBs currently glued together with scripts/polling — you actually have two separate problems: (1) reliable integration/orchestration to replace the scripts and polling, and (2) a live console where humans can see state and take action. The main tradeoff: this is a two-tool "build" approach, not a single "buy" product — it gives you real reliability (exactly-once semantics, replay on failure) and a UI tailored to how your team actually works, but it's more setup than an all-in-one enterprise iPaaS like Workato or Tray.ai, which hand you a unified console out of the box at a much higher price ($10K–$200K+/yr) and with less flexibility for custom operator workflows. If you don't need Temporal-grade durability guarantees, n8n is the lighter-weight substitute for the orchestration half.
